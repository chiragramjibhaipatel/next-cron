## Scheduled Task with Vercel Cron Jobs

This project includes a simple scheduled task that logs a message to the server console. It's configured to be triggered by Vercel Cron Jobs when deployed to Vercel.

**Core Components:**

*   **API Route (`src/app/api/scheduler/route.ts`):** This is the endpoint that Vercel Cron will call. It contains the logic to be executed on schedule (currently, it just logs a message).
*   **Vercel Configuration (`vercel.json`):** This file defines the cron job, specifying its schedule (`* * * * *` - every minute) and the API path (`/api/scheduler`) to hit.
*   **Environment Variable (`GITHUB_ACTIONS_SECRET`):** Used to protect the API endpoint. The cron job sends this secret as a Bearer token, and the API route verifies it. See `.env.example`.

**How it Works (on Vercel):**

1.  When you deploy this project to Vercel, the `vercel.json` file configures a cron job.
2.  Every minute, Vercel's infrastructure will make a GET request to your deployed `/api/scheduler` endpoint.
3.  This request will include an `Authorization: Bearer <your_secret_value>` header, where `<your_secret_value>` is taken from the `GITHUB_ACTIONS_SECRET` environment variable you set in your Vercel project settings.
4.  The API route verifies the token. If valid, it executes its task (logs a message) and returns a success response.
5.  You can view these logs in your Vercel project's "Functions" tab by selecting the `/api/scheduler` function.

**Setting up on Vercel:**

1.  **Deploy your project to Vercel.**
2.  **Set the Environment Variable:**
    *   Go to your project settings on Vercel.
    *   Navigate to "Environment Variables".
    *   Add a new variable named `GITHUB_ACTIONS_SECRET`.
    *   Set its value to a strong, random secret string (e.g., generated by a password manager).
    *   Ensure this variable is available to your Production, Preview, and Development environments as needed.
3.  **The cron job will automatically be active** based on the `vercel.json` configuration. You can monitor its invocations and logs through the Vercel dashboard.

**Testing Locally:**

The `vercel.json` cron configuration only applies when deployed to Vercel. To test the API endpoint locally:

1.  **Start the development server:**
    ```bash
    npm run dev
    ```
2.  **Set the `GITHUB_ACTIONS_SECRET` (Optional for Local):**
    *   You can create a `.env.local` file at the root of the project and add `GITHUB_ACTIONS_SECRET="your_test_secret"`.
    *   If `GITHUB_ACTIONS_SECRET` is *not* set, the API route will bypass the authorization check during local development (`NODE_ENV === 'development'`) for convenience.
3.  **Call the API endpoint:**
    Use a tool like `curl` or Postman to send a GET request to `http://localhost:3000/api/scheduler`.

    *   **If `GITHUB_ACTIONS_SECRET` is set locally:**
        ```bash
        curl -H "Authorization: Bearer your_test_secret" http://localhost:3000/api/scheduler
        ```
    *   **If `GITHUB_ACTIONS_SECRET` is NOT set locally (auth bypassed):**
        ```bash
        curl http://localhost:3000/api/scheduler
        ```
4.  **Observe the logs:**
    Check your terminal (where `npm run dev` is running). You should see a log message like:
    ```
    [Vercel Cron Task] Executed at: {timestamp} - This message is logged by the scheduled task.
    ```
    And the API will return a JSON response like:
    `{"message":"Cron job executed successfully.","timestamp":"..."}`
